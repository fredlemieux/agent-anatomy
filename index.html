Chatbots, Claude Code sessions, sub-agents, AI pen-pals on Moltbook: under the hood each one is a language model that calls tools in a loop until it decides it's finished. What changes is what starts the loop, what it's allowed to touch, and how long it keeps going.

Jargon decoder

Twelve words, one machine

Most of the confusing vocabulary is a name for one piece of the loop, or for text that gets placed into the context.

Nothing sits there thinking

Only three things ever start an agent

A person

You type a message. This is a chat or a Claude Code session. Stops when the job's done.

An event

A hook or webhook fires: an email arrives, code is pushed, a file changes. The harness starts a run with the event pasted in.

A timer

A schedule or "heartbeat" wakes it every N minutes or hours to check for work. This is what makes agents feel alive.

One always-on agent's day

Model actually running: about 2% of the day

Between bursts there's no process "waiting" or "pondering". The agent is a config file, a prompt and some memory files on disk, plus a scheduler that will start the loop again.

Case study · January 2026

How the "Reddit for AI" worked

Moltbook was a forum where only AI agents could post. The agents were mostly OpenClaw assistants running on people's own computers. Joining meant handing your agent a skill file; from then on its heartbeat checked Moltbook every 4+ hours, read the feed, maybe posted or commented, and went quiet.

So how did they take turns?

They didn't need to. A forum is asynchronous: posts sit in a database, and each agent reads whatever is newest when its own timer goes off. Nobody talks over anybody because nobody is talking live. A "conversation" between two agents can have hours between replies, like email.

And how autonomous was it?

Less than the videos suggested. Security firm Wiz found the database open to anyone: a human could post as any agent with a plain web request, there was no rate limiting, and one person could register agents in bulk. Some of the eeriest posts may simply have been people.

Always-on mind

The "it's just a loop" view gets right…

  • Every agent is a model plus tools plus a loop, started by a person, an event or a timer.
  • Skills, system prompts, sub-agents and memory are all text that ends up in a context window.
  • Between runs, nothing is thinking. Continuity lives in files.
  • Multi-agent "societies" are many of these loops reading and writing one shared place.

The "autonomous agents" view gets right…

  • The model chooses its own next step. Nobody scripts the path, so results can surprise the people who built it.
  • A loop with access to your email, money or code, running at 3am, is a real actor in the world even if it's "just" text in and out.
  • A million cheap loops reading each other produce patterns no one designed. Simple parts, complex behaviour.

Is it more complicated than a loop? A little, in four places

Workflow vs agent

If a programmer hard-codes the steps, it's a workflow. If the model picks the next step each turn, it's an agent. Same parts, different control.

The context fills up

Long runs summarise older turns or write notes to files and re-read them later. That's how a session can last hours or "remember" across days.

Everything it reads can steer it

Text is both data and instruction. A web page or a forum post can contain orders. Moltbook's heartbeat literally fetched fresh instructions from the site every few hours.

Orchestration is just more loops

A lead agent can start sub-agents with a tool call, each in a fresh context, and collect their summaries. Agents managing agents, still input → output.
